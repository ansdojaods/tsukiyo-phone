# 月夜来信 v2.5 使用与开发说明

内部版本 `2.5.0`。从 v2.0 升级时保留旧手机命名空间与存档；新增工作台在本聊天的手机数据 `studio` 中保存，旧 AVS 在 `visual` 中继续工作。已有开关沿用原存档；新增注入开关默认关闭。

## 安装

1. 备份原卡、聊天和完整手机存档。
2. 用 `releases/月夜来信小手机_酒馆助手导入版_v2.5_剧情工作台.json` 升级独立手机；或导入单独交付的大奉卡，使用它内嵌的手机。
3. **独立手机和卡内手机二选一**。大奉卡有专用开场/联系人/三清适配，不要用通用JS覆盖。
4. 停用重复的旧手机、原AVS核心/浮窗。如果已安装本次参考的事件/NPC/世界推演插件，先关闭重叠功能，避免多方注入与重复费用。手机不能保证探测其他隔离iframe的插件。
5. 刷新酒馆，在副本聊天中手动测试一次，再按需启用正文注入。

## 一、编辑视觉资料库

路径：**视觉档案 → 编辑视觉资料库**。

- 内置290条均可编辑标题、关键词、正文；支持新增、搜索、分页、停用、恢复原条目、恢复全库、JSON导入导出。
- 修改只作用于**当前聊天**，不改原世界书文件或另一张卡。希望复用时导出规则JSON，在目标聊天明确导入。
- “启用条目”决定是否保留为有效资料；**“参与视觉分析”**决定是否向视觉API发送。仅仅编辑并不会自动将整本书灌入模型。
- 默认仍选13条工作流主题。编辑其正文后，会按编辑后的完整内容参与预算；其他新选择条目也是完整正文。
- 总规则预算6000字符；超预算整条跳过，不截半条指令，页面显示跳过数并标记对应条目。标题也占预算。
- 一条正文最多12000字符、关键词最多30个；覆盖/自建记录最多450条；整个工作台存档上限2MB。
- 导出格式 `tsukiyo-visual-rules-1`；导入先整批校验，重复/危险ID或格式错误不会半途覆盖。导入会替换当前聊天的规则覆盖层，请先导出。
- 资料中的规则不能取消系统的事实/适龄约束；普通外观以原文为准，未知仍留白。原世界书只是参考，不是全部运行策略。

## 二、剧情工作台 → 事件导演

原“剧情规划”点线面仍在；其中新增工作台入口。也可从手机桌面直接打开“剧情工作台”。

1. 配好“候选事件导演”API模块，点击“生成候选池”，或直接“手写事件”。
2. 浏览候选（详情会剧透作者后台），可以“启用此事件”，也可以“按概率抽取”。
3. 抽取概率默认25%，权重1—100；同一正文前缀只记录一次抽取，即便未命中也不重复掷骰。默认冷却2条消息，随机候选有效期40条消息。
4. “导演注入”默认关，打开后才向正文模型提供当前阶段标题与钩子。secret、后续阶段、推进条件不会一并序列化。
5. 先让正文实际演绎，再点“核实正文后下一阶段”，粘贴新的角色回复中的原句。必须有比当前阶段锚点更新的角色正文，不能在同一楼层连点跳完。
6. 最后一阶段确认收束后，或主动取消后，清除本工作台导演注入。

**互斥**：当前导演生效时，旧点线面自动推演与规划注入让行，原规划数据不删；取消或关导演后恢复原功能设置。候选草稿不代表真实事件、玩家选择或最终胜负。删除/改写来源分支后记录失效，需要重新选择/生成，不承诺无限历史自动回滚。

## 三、众生侧写

- 从已有联系人加入名单，写下本人确实知道的场外参考。
- **逐人确认本轮离场**；新正文到来后确认失效，需再确认。
- 在场名单里的人、当前角色正文直接点名的人保守跳过（仅被提到也可能跳过）；不靠一次检测失败就把所有人当离场。
- 一次最多3人、1次API调用。批次缺少人物就保持缺少，不额外补请求、不自动换模型。
- 输入只包含剧情日期时间、各自人物资料/备注/已核准状态与本人亲历记忆，不传主角现场正文、全局私聊或其他未授权共同记忆。
- 结果是**侧写草稿**；可收藏或删除，但不自动插进聊天楼层、正文、MVU、记忆或世界状态。
- 多人同批模型仍可能混淆知情范围，需人工审核。本版有意不采用原插件“正文下折叠块”和自动记忆写入，避免把创作候选直接当事实。

## 四、世界状态

“从正文提取状态建议”只针对已存在的联系人，读取近期正文中的明确依据；当前现场角色排除。

- 模型可提议：位置、状态、有效至时间、原文引句。
- 不修改：人物性格、人设、关系基线、原世界书、MVU；不自动新建NPC。
- 结果先到待审核区，核对依据后“核准采用”。也可手动确认/编辑状态。
- 有效期格式 `YYYY-MM-DDTHH:MM`，可以留空。以剧情日期/时刻判定，未知时钟不把有限期状态当仍然有效；不参考电脑现在时间。
- “场外状态注入”需另开。已在当前现场的人不注入旧的场外状态；场外信息也不等于玩家或旁人自动知情。

引句存在性校验不能证明模型正确理解了句子，因此仍需审核。新增状态账本不是完整的 WorldEngine 关系树/自动演化替代品。

## 五、亲历记忆

采用CMCC的“本人共同经历”与存档隔离原则，不整套接入跨世界陪伴。

- 手动选择亲历联系人、填写共同经历和依据；能查看、编辑、删除。
- 本人的侧写只能读到明确登记给本人的条目。
- “亲历记忆注入”默认关；打开后只选当前在场联系人相关记忆，并标出知情人。
- 不自动添加跨界同伴，不导入其他存档经历，不读写CMCC世界书，不兼容它的 `_cmcc` 导出格式。
- 原手机“记忆”及记忆世界书功能仍然保留，没有用这个小账本替换它们。

## 六、输入、预算与备份

“输入与日志”可开关正文、人物档案、本人记忆输入，填写世界观补充，预览下次任务的系统/用户资料及长度，查看本页加载期间最后一次提交给手机API路由器的输入（不含密钥、底层传输封装；通用自定义系统提示词另列）。

- 新增 `director` / `parallel` / `world` 三条模块路由，支持手机现有的跟随酒馆或自定义API方案。
- 新工作台只手动调用，每聊天合计12次/小时；失败也计预算。原有AVS、主动消息、点线面功能仍沿用各自已有设置和预算。
- 推荐生成方案输出额度4096—8192 token。格式错误、超时、切聊天、停止、输入变更或模块禁用后拒绝过期结果。
- 停止无法保证撤回已到达供应商的请求/计费。
- 候选池最多40条；侧写名单30人；草稿含历史最多100条；正式状态100条；亲历记忆200条。满额时明确报错，导出后清理，不默默删旧数据。
- “导出工作台数据”是只读审阅/归档JSON，包含作者后台与私有记忆，请勿公开。恢复请使用**手机完整备份**；没有独立工作台JSON恢复入口。
- 视觉规则JSON有独立导入/导出，与上述工作台归档JSON不同。

## 开发

```bash
npm ci
npm run verify
# 可选真实浏览器检查（首次需安装浏览器与系统依赖）
npx playwright install --with-deps chromium
npm run test:browser
# Python构建不联网；保留原基线+v2.0补丁链，再应用v2.5补丁
python3 patch/build_v25.py
# 支持本次核对过的1.6.3或2.0定制卡，保留其原代码差异与预置
python3 patch/build_v25.py --card /path/to/原卡.json --outdir /path/to/output
python3 test/card-preservation.py 原卡.json 升级卡.json
node test/card-engine.cjs 升级卡.json
```

- `src/studio/core.js`：数据校验、规则覆盖、事件选择、输入装配、生成、投影。
- `src/studio/ui.js`：视觉规则编辑、五页工作台、确认和审阅动作。
- `patch/apply_studio_patch.py`：严格唯一锚点的升级补丁，定制源码不符就失败，不猜测性覆盖。
- `patch/build_v25.py`：通用脚本/独立JSON/可选定制卡构建。
- `test/studio.cjs`：44项工作台/编辑器回归；旧32项视觉回归和35项记忆回归继续运行。
- 五个上游仓库的提交号、许可核对与舍弃项见 `V2.5-REPOSITORY-REVIEW.md`。

## 验证边界

Node与jsdom模拟测试、Chromium桌面及390px窄屏交互检查已执行；所有模型结果均为模拟。真实酒馆、供应商API、不同助手版本、移动端实机、跨设备同步没有实测。源码包不是线上发布证明，没有GitHub写授权时不会声称已push。
