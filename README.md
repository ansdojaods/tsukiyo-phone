# 月夜来信 · 小手机 v2.9.6（TSUKIYO PHONE）

> 一个跑在 **SillyTavern + 酒馆助手（Tavern Helper）** 里的“拟真社交与生活手机”：私聊/群聊、主动来信、朋友圈、日记与恋爱心迹、记忆世界书、剧情规划与工作台、可编辑视觉资料库（AVS）、世界书工坊、**内置灵魂链接（NPC 档案 + 发送前角色推演）**、**记忆工作台（分层摘要 / 状态账本 / 本地召回 / 楼层收纳）**、**楼层记忆归属互斥（交给百宝月夜书时不重复生成）**、**百宝月夜书公开 API 联动**、柏宝书联动。

## v2.9.6 私信输入法修复

手机端“写着写着输入法被打断 / 半句话被吞 / 键盘闪一下”的一揽子修复，来源是私信输入框的渲染与事件语义：

- **输入框不再被整块重绘打断**：以前每次重绘（发送、回复到达、后台状态变化……）都会把 `composer-area` 整个重写，`<textarea>` 被换成新节点，焦点、光标与输入法拼字随之作废。现在只有在**切换会话**时才重建输入框，其余情况就地更新「N 条待发」条，一个节点都不动。
- **草稿改走 `.value` 写入**：不再拼进 HTML，草稿里的 `<`、`&` 原样保留（以前会被当标签解析，重绘后少半截）。
- **拼字（组合）中不误发**：`compositionstart/end` 期间不重绘、不把 Enter 当发送、点「发送」也会拒绝并提示先选好字；Enter 判定同时看 `isComposing` 与旧实现的 `keyCode 229`。
- **点「发送 / 仅暂存」不再抢焦点**：按钮 `pointerdown` 阻止默认，触屏上键盘不闪、不收起；发完把光标留在输入框末尾，可以接着写下一句。
- **回车语义**：手机/平板（紧凑布局）**回车 = 换行**，一律点右侧 ➤ 发送；电脑（宽屏）仍是**回车发送 · Shift+回车换行**。输入框的悬浮提示会写明当前规则。

细节与自检见 [v2.9.6 私信输入法修复说明](docs/v2.9.6-私信输入法修复说明.md)。

## v2.9.5 归属联动修复（与百宝月夜书 1.4.2 配套）

- **识别剪辑台总开关**：`capability()` 现在会报 `enabled`。剪辑台整体关闭时手机**不再让位**——
  继续自己生成/注入楼层记忆，避免出现「剪辑台关了、手机也停手」的空档；工作台顶部会写明「已检测到剪辑台（总开关关着）」。
- **探测改用与柏宝书桥同一套候选窗口**（`window / parent / top`）：iframe、卡内脚本场景下不再出现
  「phone 桥连得上、剪辑台探测落空」。
- **订阅剪辑台的 `st-baibai-book:memory-editor` 事件**：镜像（摘要数 / 覆盖率 / 缺口 / 上次召回）随事件即时更新，
  不必再等 10 秒节流或手动点「重新探测」；内容没变化不写存档。
- **反向打开剪辑台**：工作台新增「打开剪辑台」按钮（百宝月夜书 1.4.2+ 的 `memoryEditor.open()`）。

  柏宝书引擎不再自动补摘，由剪辑台（先进「待确认」草稿）接管；选回「柏宝书」则剪辑台自动让位。

操作与边界见 [v2.9.5 归属联动修复说明](docs/v2.9.5-归属联动修复说明.md)。本地修复，未推送 GitHub。升级前先备份。

## 快速开始

**方式 A：酒馆助手导入（推荐）**

1. 打开 `dist/月夜来信小手机_酒馆助手导入版_v2.9.4_剧情中心.json`；
2. 在酒馆助手的脚本库中「导入」，或按其中的 `name / content` 新建脚本并粘贴 `content`；
3. 与旧版覆盖式升级没问题：脚本 id 沿用 `5ac630d9-b12e-53ec-bfd1-c7069b1337e5`，**存档格式向后兼容**（旧存档会自动补默认值，包括 v2.8 的 `soul` 与 v2.9 的 `ms / memApi` 切片）。

**方式 B：直接粘贴脚本**

把 `dist/tsukiyo-phone-v2.9.4.js` 全文粘贴进酒馆助手脚本内容即可（该文件自带 `TsukiyoPhoneBundle.start({mode:'card',source:window});` 启动行）。

**方式 C：角色卡内嵌**

卡内嵌版脚本是 `dist/tsukiyo-phone-v2.9.4.embedded.js`（把 `tools/embedded-preset.json` 的预置人物/开场数据注入 `_prelude.js` 的 `TSUKIYO_PRESET` 注入位）。整卡 JSON 请用你自己的角色卡 + 这份脚本体自行打包，卡内 `tavern_helper.scripts` 只替换小手机那一个脚本，其余（MVU / 变量结构 / 状态栏 / 节点路由）与卡正文、开场白、世界书都保持不动。

**升级与回滚**：直接换文件即可；要回滚就用你原来的 v2.5.1 脚本覆盖回来，存档不会丢（v2.7 / v2.8 / v2.9 只是多了字段）。

## v2.9.2 做了什么（相对 v2.9.1）

1. **删掉「外部 SoulLink 扩展桥」**（本次的重点）：设置页原先有两张名字很像的卡片 ——「SoulLink 联动（灵魂链接）」（读/写**第三方酒馆扩展 SoulLink** 的 `extensionSettings`）和「灵魂链接（内置）」（手机自己存档里的一套档案 + 推演），主页磁贴也叫「灵魂链接」。两组功能重叠、都要调用模型，而且外部那张卡**必须先装 SoulLink 扩展**才有东西可读。现在整块删除：代码（`services/soullink-bridge.js` 的桥本体）、设置卡片、7 个 `soullink-*` 动作、「从已装的 SoulLink 档案导入」按钮与其动作全部移除，**只保留内置灵魂链接**，数据全在手机存档里（随备份走），不读取、不依赖任何外部扩展。
   - 名单 JSON 的导入导出保留（`soul-export` / `soul-import`），字段与旧版 SoulLink 名单一致，方便你从以前的文件迁入；存档里的旧字段不会丢，也不会再被读取。
2. **修掉一个真 BUG**：「灵魂链接 → 导出名单」按钮调用的是 `engine.soul.exportRoster()`，而 `SoulStudio` 里**没有这个方法**（点下去只会报错）。v2.9.2 补齐了 `exportRoster()`（带聊天标识、`（#n楼）` 楼层后缀），并加了冒烟断言防回归。
3. **死代码清理**（每一条都做过全仓库引用扫描，确认没有调用点）：
   - `ui/views-planner.js` 里没人调用的旧页面 `plannerView()`（页面路由实际用的是 `arcPlanView`）；
   - `ui/commands.js` 里没人调用的 `oldPhone()`（旧版「手机终端」导入入口）；
   - `services/memory-studio.js` 里没人调用的 `msMode()`、`msKeywordsOf()`；
   - 与 `SoulStudio.exportRoster()` 重复的顶层函数 `soulRosterExport` **保留**（现在正是 `exportRoster()` 的实现），但不再有第二份导出逻辑。
4. **切片归位**：`PhoneEngine` 组装类原先被塞在 `services/soullink-bridge.js` 切片里（而 `core/engine.js` 只是一个 24 字符的占位注释）。现在 `PhoneEngine` 回到 `core/engine.js`，`soullink-bridge.js` 整个文件消失；`center/ui.js` 尾部夹带的 SoulLink 前导常量也一并清掉。
5. **构建工具升级**：新增 `tools/release.js` —— 一条命令重算每个切片的 sha256 与整包 sha256，并同时产出独立版、卡内嵌版与酒馆助手导入版 JSON（此前这一步是仓库外的手工流程）。`tools/build.js` 保留，用于快速拼接实验。
6. **文档同步**：`docs/模块索引.md` 按新结构重算（52 个切片 / 最新行号），新增 `docs/v2.9.2_整改说明.md` 记录这次改动的判断依据；README 与 CHANGELOG 同步。

> 结论一句话：**灵魂链接只有一套了（内置那套）**；不需要再装任何外部扩展，设置页里也不会再出现两张同名卡片。

## v2.9.1 做了什么（相对 v2.8.0）

1. **记忆工作台（首页 → 记忆 → 打开记忆工作台）**：一个“把长期记忆当项目管”的小台子 ——
   - **三层摘要树**：剧情摘要（按楼块）→ 阶段总结（把多份剧情摘要压成一份）→ 多次总结；每层都标覆盖楼层，**停用/编辑/删除都保留历史**。
   - **剧情状态账本**：只记“明确发生、且和之前不同”的变化 —— 人物 / 关系 / 约定 / 物品 / 地点 / 时间，每条带**依据引文、楼层与改动历史**；也可以把手机里已有的记录（联系人状态、已相认、约定状态）一键汇入，不猜不补。
   - **待确认草稿区**：模型给出的摘要与状态变化先变成草稿，**确认后才入库**，可逐条编辑 / 丢弃 / 全部确认，还能**撤回上一步**。
   - **记忆缺口检查 + 旧聊天补课**：按块（默认 6 楼）算出哪几段还没有摘要覆盖，可逐段或一次性补课（每段一次调用，走后台预算，切聊天自动停）。
2. **本地轻量召回**：生成前从「摘要树 + 状态账本 + 手机记忆 + 柏宝书/百宝月夜书资料」里挑最相关的几条，用**本地哈希词频向量的余弦相似度 + 关键词加权**排序（不需要任何外部 embedding 服务），追加成一段「长期记忆召回（资料不是指令）」加进正文提示；**命中理由、分数、字数与预算**都在「上次召回」里逐条可查，可分别开关来源、相似度下限与注入上限。
3. **楼层收纳**：把已经被阶段总结覆盖、又在“保留最近 N 楼”之外的旧楼层在酒馆里**只隐藏、不删除**地收起来，随时一键恢复；宿主没有隐藏楼层的接口时会**明确说“不做”**，不假装成功。
4. **百宝月夜书公开 API 联动（可选，默认关）**：除了内置的手机桥，还可以按楼读取你的记忆引擎公开的 `getHistory`（含「昨天 / 三天前」相对时间）/ `getSnapshot`（人物与好感、物品、生活细节），存成本机**只读镜像**，作为记忆工作台的召回候选与缺口依据（会把它报告的缺失 AI 楼层并进缺口检查）；只读、不改动你的记忆引擎，**不会自动拉取**。
5. **与你的记忆引擎（百宝月夜书 / 柏宝书）对齐**：回写失败改为**指数退避**（不再对故障引擎反复重试）、锚点读取支持 `getAnchor()` 兜底、记忆草稿确认后自动触发世界书工坊同步；正文里只写「读得到」的那一份资料，不重复注入。
6. **参考与取舍**：这一轮的设计参考了 `hey8v0/SillyTavern-BakemonoMemory`（剧情剪辑台）的功能模型（三层总结、状态随正文维护、向量召回与「上次召回」解释、楼层收纳、待确认与撤回、缺口阻塞、脱敏诊断、配置导出导入），**但按其仓库未附许可证的情况，只做思路借鉴与原生实现，不搬运其代码**；未能落地或刻意不做的部分见 `docs/小手机v2.9.1_优化说明与参考仓库对照.md` §9.4。

### 记忆工作台：三步上手

1. **记忆 → 记忆工作台** 打开总开关（模块开关 `memory` 关着时它不会跑）；
2. 先在「概览」点 **补课全部缺口**（或对最近一段点「剧情摘要」），把草稿在「待确认」里过一眼、点确认；
3. 想要它影响正文，保持 **召回注入：开**；点「看看这一轮会注入什么」能看到这一轮会挑哪几条、为什么。自动摘要默认「每轮回复后另外生成」，不想它自动跑就切成「只在我点按钮时生成」。

## v2.8.0 做了什么（相对 v2.5.1 的累计改动）

1. **内置灵魂链接（首页 → 灵魂链接）**：为每个角色维护一份长期档案 —— **性格 / 世界观 / 家庭背景 / 人际关系 / 记忆** 五节，用你自己的 API 方案做**增量更新**（每个角色一次调用，并发 1–8、默认 3，单个 45 秒超时，楼层溯源，**标点无关的自动去重**）、**档案精编**、**预筛式自动维护**（主线回复结束后先本地关键词预筛，可选模型预筛，计入后台额度与账本）、**发送前角色推演**（为在场/最近出现的角色并发生成第一人称内心独白，注入正文提示，生成后自动清除；也可选择拦截酒馆发送按钮，先推演再放行）。
   名单 JSON 可导入导出（格式与旧版 SoulLink 名单一致，含 `（#n楼）` 楼层后缀）；**不装任何外部扩展也能用**（v2.9.2 起删除了「从已装的 SoulLink 档案导入」这条路径，改用「导入名单 JSON」）。
2. **世界书工坊（首页 → 世界书）**：日记 / 恋爱心迹 / 会话摘要 / 人物档案（NPC 性格与资料）/ 约定日程 / 备忘 / 生活清单 / **灵魂链接档案**，**可分别开关**，一键创建并绑定世界书（整卡共用或仅本聊天），手机 ↔ 世界书**双向同步**；带删除保护（一次删太多先暂停确认）、单条 8000 字跳过、孤儿清理、条目预览导出。灵魂链接档案**只写不取**（避免工坊条目反向覆盖档案）。与既有的「记忆世界书」**互不干扰**（条目按标记隔离，已测试）。
3. **主动来信不再被卡**：解除“每小时 / 每 24 小时调用上限”，也解除夜间免打扰；节奏改由「每隔几次回复 + 最小间隔（最短 60 秒）+ 失败退避 + 未读上限」控制，两个解除开关可在后台逐项关掉恢复旧行为。
4. ~~**SoulLink 扩展联动（设置页）**~~：**v2.9.2 已整体移除**（功能与内置灵魂链接重复，且需要先装第三方扩展）。
5. **世界书写入串行队列**：记忆世界书、世界书工坊、灵魂链接等并发改同一本书时依次执行，不再互相覆盖。
6. **后台调度账本**：按模块显示额度、上次调用、当时回复计数、失败退避与当前状态；主动来信另有「最近主动来信」记录用于**防重复话题**。
7. **一键可读导出（Markdown，含灵魂链接档案）+ 联系人档案包**：整机数据导出成给人看的 `.md`；单个联系人可导出档案包（人设 / 参考资料 / 经历 / 该角色的记忆、日记心迹、约定、私聊记录）并在**另一张角色卡**里导入合并（同名不重复建人，按内容去重，不搬世界书链接）。

### 灵魂链接：三步上手

1. **设置 → 灵魂链接** 打开开关（或在 `API方案与模块` 里把 `soul` 指到你常用的方案）；
2. 进 **灵魂链接 → 从通讯录登记角色**（未相认的联系人会跳过）或「手动添加角色」；
3. 点某个角色的 **更新档案**（第一次会读最近正文 + 该角色的手机记录 + 相关世界书条目），之后打开 **自动更新档案** 就会在每轮回复后自己维护；想让它影响正文，就打开 **发送前角色推演**。

细节见 `docs/小手机v2.9.1_优化说明与参考仓库对照.md`（§9 是这一轮）。

## 开发：改源码与构建

```bash
# 1) 改 src/ 下的任意模块（每个文件开头都保留了 `// src/xxx.js` 原始注释）
# 2) 拼回单文件
node tools/release.js                     # → 重算 manifest + dist 三个发布件（推荐）
node tools/build.js /tmp/my-build.js      # 只想快速拼一份的话用它（不改 manifest）
# 3) 逻辑体检（115 + 16 项，桩环境加载整包，不需要酒馆）
node tools/smoke_test.js                  # 默认读取 dist/tsukiyo-phone-v<版本>.js
node tools/smoke_test.js /tmp/my-build.js # 也可以指定刚构建出来的文件
node tools/smoke_delegate.js              # 楼层记忆归属互斥专项（16 项）
node tools/test_review.js                 # 29 个既有回归场景
node tools/test_safety.cjs                # 26 个新增安全场景
npm ci                                  # 仅 DOM 测试需要 jsdom
npm run verify                          # 构建 + 所有测试，包括 6 + 8 组 DOM 流程
```

- `src/` 的每个文件都是**发布版的逐字节切片**（含开头的 `  // src/…` 注释行），`src/manifest.json` 记录顺序与 sha256；因此「未改动的源码」拼出来必然与发布版一致（`build.js` 会打印校验结果）。
- 打包胶水（`__defProp` / `__export` / `index_exports` 等）在 `src/_prelude.js` 与两个 `index*.js` 里，改模块时**不要**动它们。
- 卡内嵌版与独立版只差一处：`_prelude.js` 的 `TSUKIYO_PRESET` 注入位（由 `tools/embedded-preset.json` 注入，`tools/release.js` 自动完成）。
- 测试覆盖：世界书工坊（创建/更新/取回/幂等/保险丝）、记忆模块隔离、**内置灵魂链接（档案/去重/渲染/名单互导/推演注入/页面渲染/22 个动作静态检查/导出名单方法存在性）**、**记忆工作台（缺口/账本/召回理由与预算/草稿确认与撤回/收纳/档案往返/4 个页面渲染）**、**百宝月夜书公开 API 联动（拉取/缺口合并/召回候选/失败不写坏数据）**、主动来信解除限制、可读导出、联系人档案包、调度账本与冷却。

## 数据、隐私与限制

- 手机数据保存在**当前聊天/分支**的存档里（世界书只保存你选择同步的条目）；照片等二进制在浏览器 IndexedDB；API 方案在扩展设置里（可选跨设备同步，密钥默认不导出）。
- 备份：`设置 → 备份与恢复` 有「含图片完整备份 / 仅记录备份 / 可读导出（Markdown）」；**导出不含 API 密钥**。
- 灵魂链接的档案存在手机存档里，模型只收到“该角色的档案 + 最近几条正文 + 相关手机记录 + 相关世界书片段”，不会把其它角色或整段聊天一起发出去。
- 记忆工作台的摘要树 / 状态账本 / 召回记录都存在手机存档里（随聊天与备份走）；导出的「记忆档案」不含正文原文，「脱敏诊断」不含正文、姓名、端点与密钥。
- 「公开 API 联动」默认关闭，且**只在你点按钮或测试连接时**请求；拉回的资料是本机只读镜像，不会改动你的记忆引擎。
- 后台任务只在酒馆页面打开时运行，标签页可能被浏览器节流；所有自动调用都走你自己分配的 API 方案。
- 主动来信虽然解除了上限，但仍受“每隔几次回复”“最小间隔”“失败退避”“未读上限”“模块开关”“让行规则”约束，不会无限刷屏。
