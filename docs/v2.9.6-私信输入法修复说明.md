# v2.9.6 · 私信输入法修复说明

> 适用：`dist/tsukiyo-phone-v2.9.6.js`（独立版）/ `…embedded.js` / `月夜来信小手机_酒馆助手导入版_v2.9.6_剧情中心.json`
> 关键词：输入法被打断、写到一半没了、键盘闪一下、回车把半句话发出去。

## 1. 你遇到的现象与真因

私信（对话页）输入时「莫名其妙被打断输入法」，由三处叠加造成——都不是输入法本身的问题，而是输入框的渲染方式：

| 现象 | 真因 |
| --- | --- |
| 写完半句，一发送/一收到回复，字没了、光标没了、候选框没了 | `renderer` 每次重绘都把 `#composer-area` 的 `innerHTML` 整个重写。发消息后「待发条」数量变化 → 重绘 → `<textarea>` 换成**新节点**，焦点、光标、输入法组合状态一起作废。回复到达、后台心跳、侧栏状态刷新同理 |
| 手机键盘「闪一下又收起来」 | 点「发送 / 仅暂存」按钮时，触屏浏览器把焦点从输入框移走 → 键盘收起；代码再 `focus()` 回来 |
| 草稿里带 `<`、`&` 时重绘后内容缺一截 | 草稿被拼进 `<textarea>${草稿}</textarea>`，尖括号与实体符被当作 HTML 解析 |

## 2. 修复后的行为（v2.9.6）

- **输入框只在切换会话时重建。** 其余情况只就地对账「N 条待发 · 尚未交给模型」这一条（`data-slot="pending"`），连一个节点都不动，焦点/光标/输入法拼字全程不受影响。
- **草稿一律走 `.value` 写入**，不经过 HTML；`<`、`&`、引号原样保留；输入框加 `autocomplete="off"`。
- **输入法拼字（组合）期间**：
  - 不重绘输入框；
  - **Enter 不发送**（判定 `isComposing` + `keyCode 229` 双保险）；
  - 点「发送 / 仅暂存」会被拒绝并提示「输入法还在拼字：先选好字，再点发送。」——不会把半截拼音发出去。
- **不抢焦点**：发送/暂存按钮的 `pointerdown` 默认行为被阻止，触屏上键盘不闪、不收起；发送完成后光标回到输入框末尾，可以接着写下一句。
- **回车语义（按你说的改）**：
  - 手机 / 平板（紧凑布局）：**回车 = 换行**，发送一律点右侧 ➤；
  - 电脑（宽屏）：**回车发送 · Shift+回车换行**；
  - 输入框的悬浮提示会写明当前规则（「回车换行 · 点右侧 ➤ 发送」/「回车发送 · Shift+回车换行」）。
- 未变化：发送失败/成功提示、待发箱、`+` 工具、表情、图片附件、朗读等原有交互一律不动。

## 5. 边界

- 组合语义在真实手机浏览器上还会受各家输入法（微信键盘、搜狗、Gboard）与酒馆 WebView 的影响；本版把可控的三条链路（重绘打断、抢焦点、组合误发）都堵上，并在输入框提示当前回车规则。
- `jsdom` 不模拟真实输入法，专项用例验证的是**事件与节点语义**（谁被拦截、谁被重建），不代表真机端到端。
- 其它页面的多行输入（便签、日记、提示词等弹窗）走的是 `<form>` 表单、不参与每次重绘，本轮未改动。
