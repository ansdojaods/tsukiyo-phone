# v2.5：五个仓库的阅读与整合取舍

阅读日期：2026-10-06。通过公开 Git 仓库浅克隆，阅读 README、许可证（如有）、manifest 与以下关键实现。没有执行五个项目的运行脚本，没有把它们的扩展入口直接拼进手机。

本版新增代码在 `src/studio/`，是针对手机现有任务队列、API 路由、存档与 UI 的独立实现。以下是设计参考而非二进制兼容/完整移植承诺。五个参考仓库的完整源码未放进交付包。

## 1. random-event-director

- 地址：https://github.com/lucigra-Red/random-event-director
- manifest 版本：0.1.8
- 阅读提交：`5b7043bb7827a091e66fd84935928676655b2ff4`
- 关键阅读：README、LICENSE、`engine.js` 中事件解析、候选池、随机选择、聊天标识、refill、生成拦截、回合重放与完成确认。
- 许可文件：MIT。

**用途**：提前生成候选事件池，按聊天独立配置概率，在正文生成前挑出事件；原实现用回合锚点重放，避免每次重生成都换随机条件。

**取长**：候选池、权重、概率、避免重复、聊天隔离、候选有效期，额外调用前可审阅输入。

**v2.5 做法**：一次手动生成最多6个候选（提示请求3个），每个1—6阶段；提供概率/权重抽取，同一正文前缀记录一次抽取结果。手动选定也可绕过概率。新增模块不自动补池；候选超过40条消息后不参与随机抽取。修改/删除来源正文后失效，不宣称无限历史重放。

## 2. st-direct-event

- 地址：https://github.com/pzwtxdy831-commits/st-direct-event
- manifest 版本：0.5.2
- 阅读提交：`851acd9c577206128c20769f956a3778d0776a0d`
- 关键阅读：README、LICENSE、`index.js` 中生成/分阶段解析、当前阶段提示、注入注册与注销、提示查看器等入口与实现。
- **许可冲突**：README 写 MIT，但仓库实际 LICENSE 写“personal, non-commercial purposes only”，并限制商业使用。不能仅凭 README 当成 MIT 分发。

**用途**：副模型一次产生事件脉络，正文按阶段接收当前“小纸条”，后台信息和后续阶段不直接泄露。

**取长**：当前阶段与完整后台分离；将回应权交给玩家；取消后清理注入；可预览请求。

**v2.5 做法**：不复制其代码、预设或长篇“破限”提示词。新代码只向主模型提供当前阶段的标题与钩子，不序列化 secret、后续阶段、条件。进入下一阶段必须已有新角色正文，用户粘贴可核对原句；不按轮数自动裁定胜负。开启导演注入期间原点线面自动推演与规划注入让行，数据保留。

## 3. npc-parallel

- 地址：https://github.com/ug776732-arch/npc-parallel
- manifest 版本：1.0.7
- 阅读提交：`eb1aca9933f24171c8b3e35971f08a9c7877a680`
- 关键阅读：README、LICENSE、`index.js` 的聊天级NPC名单、在场检测 `detectPresence`、人物生成与批次/补漏相关逻辑。
- 许可文件：MIT。

**用途**：正文完成后，为不在场人物补写平行视角。原项目支持批量请求、轻量检测渠道、备用端点和补漏。

**取长**：人物名单审核、批量任务、有限视角、角色知情范围分开。

**改进取舍**：原实现的未知/检测失败可能按离场继续生成，且自动补漏/轮换可增加调用。手机采用保守策略：未确认就不生成；当前在场或当前正文直接点名的人跳过。每条新正文需重新确认离场。每次最多3人、1次调用；不做自动补漏与供应商轮换。

**v2.5 做法**：联系人加入侧写名单 → 填本人可知参考 → 确认本轮离场 → 批量生成草稿。没有向NPC请求发送主角正文或全局私聊；本人亲历记忆按ID过滤。批次内模型仍同时看到多个角色资料，不能保证其绝不串人，因此只保存为待审/收藏草稿，不自动写入正文、世界状态或记忆。

- 地址：https://github.com/WhiteShawqi/SillyTavern-CMCC
- manifest 版本：1.3.5
- 阅读提交：`2cbdf71fa5603ec4739ae1c592ee94248969ee84`

**取长**：共同亲历而非全知；区分人物、世界与存档；记忆可查看、编辑、导出。

**本版不整套移植**：不自动在大奉开场添加外来同伴，不跨卡导入关系或经历，不读写 CMCC 私有世界书，也不声称兼容它的 `_cmcc` 导出文件。新增本存档“亲历记忆”小账本，由用户指定实际参与联系人、记录依据；用于本人的侧写，正文注入需另开且标明知情人。现有手机记忆世界书功能继续保留。

**取长**：增量而非重写人设；现场保护；新数据待审；状态有效期与输入预算。

**v2.5 做法**：独立实现手机状态账本，模型只能提出已存在联系人的 `location/status/until/evidence` 建议，必须有近期正文逐字依据。用户核准后才写入账本；不修改联系人性格、关系基线、原世界书或MVU。有效期用剧情时间，不拿电脑日期推进剧情。未整套移植关系树，也不采用原项目的特定情感层级裁决、全员自动推演或有界快照外的回滚宣传。

## 共用的底层约束

- `PhoneActions.perform` + `TaskRunner` + `ApiRouter` + `BackgroundGate`，不是五套独立API/事件监听。
- 新导演/侧写/状态任务仅手动触发，合计每聊天12次/小时；失败也占本地预算。
- 本聊天存档；来源正文前缀不匹配就停止采用旧分支记录。
- 改输入、切聊天、停止、禁用模块后拒绝过期结果提交。
- 不新增后台服务器、不下载或执行五个仓库的脚本，不复制密钥。
- 世界状态、侧写和亲历记忆只在手机自己的命名空间保存，不回写第三方插件的内部状态。

## 仍需真实环境验收

自动化使用模拟模型；浏览器检查用桌面和390px Chromium视口。没有连接用户实际SillyTavern实例，没有实际调用任何模型供应商。真实助手版本、API格式/输出额度、跨设备存储能力需在备份后的聊天副本验证。
