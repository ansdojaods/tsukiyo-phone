## 灵魂链接究竟有没有与世界书联动？

**有，但不是完整双向同步。**

1. 更新角色档案时，现有实现可以读取已绑定世界书中与该角色相关的片段，作为模型整理档案的材料。
2. 在 **世界书工坊 → 同步来源 → 灵魂链接档案** 打开写出后，手机里的五节档案可以生成工坊条目。
3. **在世界书里修改一段文字，不等于自动还原为灵魂链接的五节结构。** 本版不虚构这种回灌能力，也不把跳过的回灌算作成功。生活清单的远端修改同样不自动拆回本地任务结构。
4. 工坊“人物档案”和灵魂链接“五节档案”是两个来源。前者从通讯录人物资料组织内容，后者是灵魂链接专门维护的档案。

## 批量删除的边界

### 灵魂链接

入口：**灵魂链接 → 批量删除角色**（先预览，再确认；关闭生成时显示“预览 / 批量删除已有档案”）。

- 每页 20 条，跨页选择会保留；全选作用于本页当前可见条目。
- 删除所选角色的五节档案与对应推演历史，并清理当前推演注入。
- 不删除通讯录联系人、手机记忆、日记或角色卡原始世界书。
- 如果对应灵魂条目已由当前工坊纳入同步且该来源开启，后续同步会移除其工坊条目；大量移除仍需确认。
- 正在生成、精编或推演时删掉角色，迟到结果不得将其重新创建。
- 删除不可单独撤销；需要恢复时使用删除前导出的名单/手机备份。

### 世界书工坊

入口：**世界书工坊 → 预览条目 / 批量移除**；恢复使用 **恢复已排除条目**。

- 删除只针对带本手机工坊标记的选中条目，不清空整本书，不删除第三方条目。
- 同时记录持久“排除清单”，防止下一轮自动同步把刚删的条目又写出来。
- 手机中的联系人、日记、便签等原始数据保留。
- 远端删除失败时，排除标记仍保留；刷新后可重新选择残留远端条目重试。
- 恢复排除后，需要该来源开启、在同步条数上限内，才会再次写出。
- 连接已有书时，不自动清理没有纳入当前同步的其他工坊条目。旧版遗留孤立条目可以在管理页明确勾选删除。
- 预览包含未开启的来源；**预览不等于开启同步**。写出正文仍有 8000 字上限，超出部分不会写进世界书，手机原文不因此截断。

### 手机记忆

记忆页新增 **条目预览 / 批量删除**，展示完整正文。这里与工坊“排除写出”不同：会删除手机记忆本身，并把已关联条目的删除放入同步队列；自动同步关闭时需手动同步。未选中的记忆和工坊条目不删除。柏宝书镜像不列入这个批删入口；第三方模块应在其自己的管理界面操作。

## 怎样连接工坊已经创建的世界书？

1. 打开记忆页，点 **读取已有世界书并同步**。
2. 选择已有书；工坊已连接的书会优先显示。
3. 选择绑定当前角色卡或当前聊天。
4. 展开正文，勾选需要导入的记忆条目，再确认。

注意：

- 同一本书可以由两模块共用，但工坊的 NPC/灵魂/日记条目仍归工坊，不作为普通记忆重复导入。
- 没有普通记忆条目时，可以空选连接；不会为了“读取”而复制所有 NPC 资料。
- **手机已有记忆也会同步写入所连接的书。** 这不是只读浏览功能。
- 未选条目不作为新记忆导入；之后新增的未选条目也不会自动导入。需要增加选择时，先停止同步再重新选择；已绑定的手机记忆仍按已有绑定同步。
- 选中范围会保存到当前配置，并随“整张角色卡共用”的自动连接配置保存。
- 从旧“新建”入口遇到同名非空世界书时，记忆模块转入预览选择；工坊提示改用已有书入口，不静默覆盖。

## 额外修复

- **首次来源顺序**：选择“只写人物”等来源后，先保存选择，再做首次同步，避免先写进默认的日记等数据。
- **人物取回稳定性**：远端人物修改作为参考资料保存；记录取回后的本地基准，避免下一次同步又被旧简介覆盖。
- **双方同时修改**：工坊保留手机与世界书两份内容并提示冲突，不静默选择一边覆盖；需要人工核对。普通记忆同步原有的冲突/旧内容恢复机制没有被改成同一套策略。
- **超长内容**：同步哈希以实际写出的截断正文计算，避免同一篇长档案每轮都被判定有新修改。
- **事务落盘**：手机记录合入灵魂档案改为修改待提交的数据副本。
- **上下文保护**：新预览/批删、模型结果提交和同步主流程检测聊天、分支、正文或本地输入变化；旧操作不跨聊天继续提交。
- **构建修复**：输出目录缺失时可重建；重复构建不累加导入说明；清除旧版发行文件，避免混装。源码包包含可复现的构建与测试入口。

## 测试结果与限制

本版通过：

- 原逻辑冒烟 **115 项**；归属互斥专项 **16 项**。
- 新增 **29 个回归场景**：路由、特殊名字、分页保留、取消、跨聊天、删除排除/恢复、第三方条目保护、远端并发变化、失败重试、首次来源选择、长文本幂等、人物取回幂等、冲突保留、同书记忆导入、迟到模型结果、手机记录落盘等。
- **6 组 jsdom 实际 DOM 流程**：点击已生成档案、勾选并确认角色批删、工坊类别预览与批删、读取已有工坊书并选择记忆、记忆预览批删及对应远端清理、跨页选中。
- 独立版和内嵌版 JavaScript 语法检查；发行清单、源码拼装、JSON 内脚本一致性及重复构建检查。

完整日志在 `verification/`。逻辑测试使用宿主/API 桩；DOM 测试使用真实 UI 代码和表单事件，但世界书接口及模型调用仍是桩。

**没有在你的真实酒馆、真实聊天存档、真实供应商 API 上完成端到端验证。**

手机存档与酒馆世界书属于两个系统，无法保证跨系统原子事务：若世界书写入成功后恰好发生聊天切换，本地提交可能被拒绝，远端已经完成的写入无法保证回滚。应先备份，在测试聊天验证后再用于主存档；异常后核对双方内容再重试。

## 安装与源码

1. 备份手机存档、灵魂名单及相关世界书。
2. 停用旧版独立脚本，避免两份手机脚本同时工作。
3. 在酒馆助手导入包内 `01_酒馆助手导入/` 的 JSON。
4. 刷新酒馆，在测试聊天检查档案、批删和已有书连接。
5. 若要回退，恢复升级前的匹配备份，不假定旧版能无损处理所有新字段。

`02_脚本/` 中的 embedded 脚本沿用**本仓库既有预置**，不是重新制作的八卡合集。不要把一个通用预置直接覆盖八张卡各自的联系人、开场和剧情时间。

`03_源码/` 解压后：

```sh
node tools/release.js    # 无需安装依赖即可生成发行文件
npm ci                  # 安装 DOM 测试依赖
npm run verify          # 构建、冒烟、回归与 DOM 测试
```
