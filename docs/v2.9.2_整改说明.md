# 小手机 v2.9.2 整改说明（SoulLink 重复问题 · 死代码 · 构建工具）

> 对应仓库：`tsukiyo-phone`（月夜来信 · 小手机）
> 基线：v2.9.1 → 本次 v2.9.2。改动都在源码与工具里，**存档格式不变**，可以直接覆盖升级。

## 一、你问的「设置里的 SoulLink 联动」和「主页里的灵魂链接」是不是重复？

**是重复的，而且不是同一套东西。** v2.9.1 里「灵魂链接」这个名字下其实有两条并行的链路：

| | 设置页的「SoulLink 联动（灵魂链接）」 | 主页磁贴 / 设置页的「灵魂链接（内置）」 |
| --- | --- | --- |
| 数据放在哪 | **第三方酒馆扩展 SoulLink** 的 `extensionSettings`（要你先装那个扩展） | 手机自己的存档（随聊天、随备份走） |
| 谁在调用模型 | 手机代读/代写，但档案归对方 | 手机自己的 API 方案 |
| 能做什么 | 扫描档案 → 导入成手机联系人与记忆；把手机记录写回对方「记忆」分节；名单 JSON 互导 | 五节档案（性格 / 世界观 / 家庭背景 / 人际关系 / 记忆）、AI 增量维护、精编、**发送前角色推演**、名单导入导出、世界书工坊的「灵魂链接档案」来源 |
| 前提 | **必须先安装并启用 SoulLink 扩展**，否则设置页那张卡片只会写「没有检测到」 | 装了手机就能用，不需要任何外部扩展 |

两组功能高度重叠（同一套五节档案模型），同时开着会**对同一批角色重复调用模型**，界面上两处都叫「灵魂链接」也很难分辨。既然你希望「如果要用插件就把它清掉」，本次就把外部那一整套删干净：

- 代码：`src/services/soullink-bridge.js` 里的 `SoulLinkBridge` 类整体删除（约 290 行，含扫描 `extensionSettings`、pull / push / 名单互导、`SOULLINK_SECTIONS`、`soulDefaults`）。
- 界面：`src/ui/views-settings.js` 的 `soullinkCard()` 卡片与其挂载点删除；名单页的「从已装的 SoulLink 档案导入」按钮删除。
- 动作：`src/ui/commands.js` 的 `soullink-toggle / soullink-write / soullink-scan / soullink-pull / soullink-push / soullink-export / soullink-import` 七个分支、以及 `soul-import-extension` 分支删除。
- 保留：**名单 JSON 的导入导出**（`soul-export` / `soul-import`），字段继续兼容旧版 SoulLink 名单（`app / kind / roster`、`（#n楼）` 楼层后缀），所以从老文件迁入仍然可以；只是不再主动去读别人的扩展设置。
- 存档里的旧字段不会被删（导入旧备份也不会报错），只是手机不再读取它们。

> 现在「灵魂链接」只有一套：主页磁贴 → 内置灵魂链接 → 档案 / 推演 / 名单导入导出。**不需要再安装任何外部插件。**

## 二、顺手修掉的一个真 BUG

`src/ui/commands.js` 的「导出名单」按钮长这样：

```js
case "soul-export": {
  const r = engine.soul.exportRoster();   // ← SoulStudio 里并没有 exportRoster()
  download(ui, "灵魂链接名单-" + ... + ".json", r);
```

`SoulStudio`（`src/services/soul.js`）只有 `analyze / condense / roleplay / pushPhoneLines / tick / ...`，**没有 `exportRoster()`** —— 点「导出名单」只会抛错。v2.9.2 补齐了该方法：

```js
exportRoster() {
  const snap = this.eng?.repo?.snapshot || {};
  let chatKey = "", chatLabel = "";
  try {
    const parts = JSON.parse(snap.owner || "[]");   // owner = [groupId, avatar, chatId]
    if (Array.isArray(parts)) { chatKey = String(parts[2] ?? ""); chatLabel = String(parts[1] ?? ""); }
  } catch { chatKey = ""; }
  return soulRosterExport(this.view(), { chatKey, chatLabel });
}
```

并在 `tools/smoke_test.js` 里加了一条断言防止回归。

## 四、为什么会有这轮改动：切片错位

v2.9.1 的 `src/services/soullink-bridge.js` 这一个切片里其实塞了两样东西：

```
src/services/soullink-bridge.js
├── SoulLinkBridge（外部扩展桥，v2.6）      ← 本次删除
└── PhoneEngine（引擎组装类，全应用的骨架） ← 本次搬到 core/engine.js
```

而 `src/core/engine.js` 当时只有一行 24 字符的占位注释 —— 也就是说**应用最核心的组装类，藏在一个叫「外部 SoulLink 桥」的文件里**。同时 `src/center/ui.js` 的尾部还夹带了 `SOULLINK_SECTIONS` / `soulDefaults` 两个常量（属于上面那段桥的前导代码，被切错了位置）。

本次把它们各归各位：`core/engine.js` 现在就是真正的 `PhoneEngine`，`soullink-bridge.js` 整个文件消失，`center/ui.js` 尾部干净了。`src/` 切片数 **53 → 52**。

## 五、构建与发布工具（新增）

之前「把 `src/` 拼回单文件」「生成卡内嵌版」「生成酒馆助手导入版 JSON」是仓库外的手工流程。现在一条命令：

```bash
node tools/release.js
```

它会：

1. 按 `src/manifest.json` 的顺序重新读取 52 个切片，重算每个切片的字符数与 sha256，并把整包 sha256 写回 manifest；
2. 写出 `dist/tsukiyo-phone-v2.9.2.js`（独立版）；
3. 把 `tools/embedded-preset.json`（大奉打更人预置人物/开场数据）注入 `_prelude.js` 的 `TSUKIYO_PRESET` 注入位，写出 `dist/tsukiyo-phone-v2.9.2.embedded.js`（卡内嵌版）；
4. 用独立版全文做 `content`，写出 `dist/月夜来信小手机_酒馆助手导入版_v2.9.2_剧情中心.json`（脚本 id 沿用 `5ac630d9-b12e-53ec-bfd1-c7069b1337e5`，覆盖式升级）；
5. 顺手删掉 `dist/` 里的旧版本产物，避免两份并存。

`tools/build.js` 保留（只拼接、不改 manifest），适合临时实验。

## 七、升级建议

1. 直接用新的导入版 JSON（或新脚本全文）覆盖旧脚本，**存档与设置都不需要动**；
2. 如果你以前用过「SoulLink 联动」那张卡导入了角色资料，那些联系人与记忆**已经落在手机存档里**，不会因为删掉桥而消失；
3. 想继续从第三方 SoulLink 迁数据：在那边「导出名单」，到手机「灵魂链接 → 导入名单」即可（字段与旧格式一致）。
