# 小手机 v2.9.5：与百宝月夜书（剧情剪辑台）的归属联动修复

配套版本：**百宝月夜书 v1.4.2**（`capability().enabled`、`memoryEditor.open()`、`autoSummaryAllowed`、菜单角标）。
本文只讲这一轮改了什么、怎么验证、有哪些边界；v2.9.4 的安全优化见 `docs/v2.9.4-安全优化说明.md`。

## 1. 修了什么

| # | 问题（v2.9.4 及更早） | 现在 |
| --- | --- | --- |
| 1 | 手机的「引擎接管」只看 `capability().available`。用户在剪辑台里把**总开关**关掉后，手机仍然让位 → **楼层记忆两头没人管**（手机不摘、剪辑台也不摘） | `capability()` 会带 `enabled`。关闭时手机**不让位**，继续生成/注入楼层记忆；工作台顶部写明「已检测到剪辑台（它的总开关是关着的）」，并在它打开后自动恢复接管 |
| 2 | 探测剪辑台只试 `window`；柏宝书 phone 桥走的是 `window → parent → top`。iframe / 卡内脚本场景下会出现「桥连得上、剪辑台探测落空」 | 统一走 `baibaiCandidates()`，与桥同口径 |
| 3 | 剪辑台广播的 `st-baibai-book:memory-editor` 事件**没人订阅**，镜像最旧要 10 秒（巡检 120 秒）才更新 | 订阅该事件，即时写入镜像；3 秒节流 + 内容去重，没变化不写存档 |
| 4 | 手机只能等用户去魔杖菜单点「剧情剪辑台」 | 归属卡片新增「打开剪辑台」按钮 → `memoryEditor.open()`（老版本给指引，不报错） |
| 5 | 与柏宝书的自动摘要可能**同时开**：同一段剧情两次模型调用 + 两个互相矛盾的缺口数字 | 归属二选一：柏宝书设置 → 摘要设置 →「自动摘要归属」选「剧情剪辑台」后，柏宝书引擎停止自动补摘（`editorOwnsAutoSummary`），剪辑台开始自动摘要；选回「柏宝书」则剪辑台让位 |

## 2. 界面上的三态

「记忆工作台 → 楼层记忆归属」现在明确区分：

- **未检测到百宝月夜书剪辑台**：手机自己管（老行为）。
- **已检测到剪辑台（它的总开关是关着的）**：手机自己管；镜像字段清空，不显示过期数据；一句话说明「在剪辑台里打开总开关后自动接管」。
- **引擎接管中**：显示剪辑台版本、覆盖 / 缺口 / 摘要数 / 待确认数 / 上次召回；手机侧自动摘要、楼层召回、补缺口停用。

## 3. 边界与注意

- 事件镜像只信 `detail.available === true` 的广播；异常一律忽略（探测失败不影响手机自己跑）。
- 「接管期间仍注入手机内记忆」开关不变：打开后只注入手机自己的记忆与生活细节，不含楼层摘要与状态账本。
- 旧版百宝月夜书（< 1.4.2）：`capability().enabled` 缺失按「开着」处理，`open()` 缺失时按钮给指引——行为与本轮之前一致，不会因升级手机而变坏。
- 依旧没有真实酒馆/真实 API 的端到端验证：测试为模拟宿主与模拟模型。
