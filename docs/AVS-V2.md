# AVS 原生视觉档案 · 月夜来信 v2.0

## 安装与升级

1. 先备份角色卡、聊天和手机存档。在酒馆助手中停用旧的 **AVS Runtime Core** 与 **AVS Floating Inspector**。保留旧聊天变量，以便迁移。
2. 独立手机导入 `releases/月夜来信小手机_酒馆助手导入版_v2.0_AVS视觉档案.json`。保持原脚本 ID，确认旧手机没有另外留下一份启用副本。
3. 如果使用已升级的大奉卡，直接使用卡内手机，不再同时启用独立手机版。大奉卡保留专用开场、联系人、三清等适配；不要拿通用 JS 覆盖卡内脚本。
4. 刷新酒馆页面，打开聊天，再打开手机 → **视觉档案**。首次可用“自检”，有旧数据则点“读取旧AVS”。
5. 点击“同步当前正文”会额外调用一次模型。自动同步、正文注入默认关闭，需分别确认开启。
6. 若之前安装了原 AVS 世界书，可解除它的常驻绑定，避免重复注入。原 290 条已作为手机内只读资料库收录；不需要再次安装原世界书。

`vendor/avs/` 是用户提供的原始参考文件，不是这次的安装入口，也不会被自动执行。

## 七页与事实策略

- 概览：身份、年龄依据、整体印象。
- 外貌：脸型、眼眉鼻唇、肤色与特征。
- 体态：身高、体型、姿态、动作习惯。
- 穿搭：普通外衣/上下装/鞋袜、材质、颜色、纹样。
- 发妆：发色、长度、发型、妆容。
- 配饰：头饰、首饰、随身物品。
- 状态：位置、表情、动作、衣着变化和外观状态。

这是对原 AVS 的原生重构，不是未经修改地拼接它的核心。**不会自动估测尺寸、补贴身衣物或私密身体细节**；未知字段明确留白，所有人物保持普通外观记录，未成年、幼态或年龄不明者尤其保持适龄。模型更新必须附输入中的连续原文引句。引句存在性校验不是语义证明，请用“查看依据”核对模型是否理解正确。

原规则库 290 条全部可搜索和分页阅读；仅挑选 13 条工作流的“本条主题”作为分析补充，控制在 3000 字符内，避免重复模板占据上下文。原文资料不等于执行策略，事实与适龄规则优先。原规则库并不整体常驻注入正文。

## API、预算与后台

- 复用手机的 `ApiRouter`、`TaskRunner`、`BackgroundGate`，有独立的“AVS视觉档案”模块路由，可跟随酒馆或指定已有独立 API 方案。
- 建议视觉专用方案配置 4096—8192 输出 token；批量人物较多时默认 1800 可能不足。输出截断/JSON错误时旧数据保留。
- 当前正文同步：一次调用最多返回 8 人；角色卡描述最多读 6000 字符，相关联系人最多 16 人、每人 1400 字符。人工选中的已建档人物优先；其余按模型与正文确定。
- 自动：当前稳定新正文最多一次，按每聊天 6 次/小时、24 次/日限制；还受跨标签页共享自动预算与后台锁约束。失败计入预算，同一轮不会紧接着反复重试。
- 手动：每聊天 30 次/小时，失败也计入预算；频率记录保存进手机存档。清空浏览器/恢复旧备份可能改变本地预算，不是服务端计费限制。
- 自动视觉开关独立于主动来信开关；关闭整个视觉 API 模块也会阻止生成、移除视觉正文注入。
- 手机隐藏时仍可工作，关闭/刷新页面则停止本页任务。沿用现有 2.2 秒刷新周期，没有再注册原 AVS 的独立 watchdog 或另一套宿主事件。
- 停止、卸载、切换聊天、修改正文或 API 配置时拒绝旧结果提交。请求已到达供应商后不保证退款或停止供应商侧计费。
- 可探测宿主/已注册脚本窗口内的旧 AVS 核心，但不能保证发现另一个完全隔离 iframe 的脚本，因此仍需手动检查脚本列表。

## 不破坏旧档案的回扫

“全量回扫（分批）”每点击一次，仅处理最多 4 条角色正文、发起 1 次调用，确认框会显示整段聊天预计调用数。不是一次点击就无限扫描整个聊天。

- 中间结果写入 `visual.scan` 草稿，正式档案不清空。
- 失败时保留游标与正式档案，修复 API 后再点继续。
- 所有批次成功后才替换正式档案，同时保存一份回扫前备份，可交换恢复。
- 回扫期间自动同步暂停。取消草稿不影响正式档案。
- 正文编辑、删除、分支或新增导致签名改变后，下次回扫从头开始；手动同步当前正文会放弃旧的回扫草稿。
- 单批清洗后的正文 JSON 超过 48000 字符则明确停止，不静默截断。长聊天与超长单楼层建议先整理；全量回扫可能昂贵。

## 旧 AVS 迁移与存档隔离

读取当前聊天的 `acgn_visual_v25` / `v24` / `v23`，兼容 v2.5.1 的 `characters.*.identity.name` 与 `profile`。仅读取，**不修改原命名空间**。按白名单转换普通外观字段，不是无损导入原全部身体细项；同名手机记录不覆盖。迁移字段标记“旧档案待复核”，不直接送入正文。旧命名空间及原文件仍是完整原档案的保留处。

新档案存在手机自身存档的 `visual` 字段，继承楼层、聊天备份、本机镜像与完整手机备份/恢复。另有视觉档案专用 JSON 导出，便于审阅；专用 JSON 暂无单独导入入口，恢复请使用手机完整备份或回扫前备份。

每个角色保留最多 8 个版本（当前 + 7 个历史版本），用正文前缀指纹确定分支有效性。编辑、删除、回溯时只展示和注入仍与当前前缀匹配的版本；匹配不到则留空，而非把另一分支的外观带过来。正文注入仅当前场景相关最多 6 人、人物 JSON 最多 5200 字符（外层说明另计），不包含迁移待复核字段，不回写柏宝书摘要或其他模块的私人消息。

## 开发与可重建性

```bash
npm ci
npm run verify
# 保留原始1.5.2→1.6.3补丁链，然后应用AVS升级
python3 patch/build_v2.py
# 在原定制卡代码上升级；保留角色卡版本与原预置
python3 patch/build_v2.py --card /path/to/原卡.json --outdir /path/to/output
python3 test/card-preservation.py 原卡.json 升级卡.json
node test/card-engine.cjs 升级卡.json
```

- `src/avs/visual.js`：原生服务、资料模型、UI、动作与防护。
- `src/avs/knowledge.json`：从用户提供的 AVS 世界书抽取的全部 290 条。
- `patch/apply_visual_patch.py`：严格单一锚点的 1.6.3→2.0.0 补丁，可用于通用或大奉定制脚本。锚点不符直接失败，不猜测性覆盖。
- `patch/build_v2.py`：源码、独立导入 JSON、可选定制卡打包器。
- `test/visual.cjs`：32 项新回归（模型/宿主模拟，不调用真实 API）。

构建器支持本次上传的 1.6.3 引擎。未知版本或其他大改动需重新核对锚点，不保证任意第三方魔改卡都可直接升级。
